**Architecture:**
- **Hosting:** the app becomes a single container, a TanStack Start app built with the Nitro `node-server` preset, with pinned Python/yt-dlp/ffmpeg/curl inside the image.

- **Untrusted code:** the server executes no third-party JavaScript (D7).

- **Extension:** one redesigned MV3 extension, built and signed in CI and published to the Chrome Web Store.

**Tech Stack:** TanStack Start / React 19 / Vite 8 / Nitro (`node-server` preset), Better Auth (Google OAuth), PostgreSQL 16, Node 24 LTS, Python 3.12 + pinned yt-dlp, ffmpeg (static, pinned), Docker (OCI image on GHCR), GitHub Actions, Playwright, `node:test`.

## Global Constraints (apply to every task in every workstream)

- **Node:** `>=24.15.0` (`engines` in package.json, `.nvmrc` = `24`). The container pins `node:24.15-bookworm-slim` by digest.
- **Python:** 3.12 in the container. yt-dlp and its extras are pinned by exact version **and hash** in `requirements.txt`, installed with `pip install --require-hashes`.
- **No runtime installs.** Nothing may run `npm`/`pip`/`curl | sh` at request time or from the UI. Dependencies change only through a PR and a rebuilt image.
- **Untrusted JavaScript:** the server never executes JavaScript fetched from a third party (player JS, the BotGuard interpreter or anything else). `new Function`, `eval` and `vm.*` are forbidden in `src/`, enforced by a lint rule once W4b removes the existing uses. The circumvention features stay off (D7).
- **Egress:**
  - no free/public proxy lists and no public CORS relays (corsfix, allorigins, …);
  - server egress goes direct or through the single operator-configured `VELO_EGRESS_PROXY`;
  - the user-proxy feature keeps its existing SSRF filter;
  - after W2, no host containing `grok` may appear in `src/`, `server/`, `scripts/`, `packages/` or `public/`, enforced by a CI grep.
- **Credentials:**
  - YouTube cookies are never persisted server-side, never logged, never returned in a response;
  - only allowlisted cookie names are forwarded;
  - yt-dlp cookie files are written to `mkdtemp` with mode `0600` and removed in `finally`.
- **API routes:**
  - every `/api/*` handler except `GET /api/health` starts with `requireSameOrigin(request)`;
  - every error response is built with `apiError(...)`;
  - raw `err.message` never reaches a client.
- **Logging:** server code logs only through `log` from `src/lib/log.server.ts`. It redacts keys matching `/cookie|token|secret|authorization|password|sapisid|sid/i`. A lint rule bans `console.*` in `src/**/*.server.ts` and `src/routes/**` after W1. Exemption: `src/lib/auth/gate-session.server.ts` and `src/lib/auth/verify.server.ts` stay exempt until W2, which must delete both `ignores` lines.
- **Config:** production boot calls `loadServerEnv()`, and a missing required variable exits with a non-zero code. Dev defaults exist only when `NODE_ENV !== "production"`.
- **Tests:**
  - every P0/P1 fix lands with a regression test written first and seen failing;
  - never weaken, skip or delete a test to go green;
  - unit tests are `src/**/*.test.ts` (run by `npm test`), HTTP black-box tests are `tests/http/*.test.mjs` (run by `npm run test:http` against the built server), E2E is `tests/e2e/*.spec.ts` (Playwright, `npm run test:e2e`).
- **Lint:** after W1-T3 every rule is `error`. `npm run lint` must exit 0 with 0 warnings (`--max-warnings 0`).
- **Commits:**
  - Conventional Commits, one commit per task, on the workstream branch;
  - every commit message ends with a `Co-Authored-By:` trailer naming the model that executed the task (`Claude Opus 5.5 (1M context)` or `Claude Sonnet 5`, `<noreply@anthropic.com>`);
  - PR descriptions end with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
- **Branches:** one branch per workstream (`hardening/wN-<slug>`), each developed in its own git worktree (`superpowers:using-git-worktrees`). Merge to `main` by PR only, after CI is green (from W1 on) and the whole-branch review.
- **Windows + Linux:** every npm script must work on both (no `/tmp`, `/dev/null`, `python3` literals in Node code; use `os.tmpdir()` and the resolved interpreter). The container is Linux-only, and macOS is documented as untested until CI covers it.
- **Copy rule:** user-facing text never promises what the code doesn't do ("encrypted", "official Google", "bypass"). Security claims in docs must name the mechanism.

### C1 — `src/lib/env.server.ts` (created in W2-T2)
```ts
export type ServerEnv = {
  NODE_ENV: "development" | "test" | "production";
  DATABASE_URL: string | undefined;        // required in production
  BETTER_AUTH_SECRET: string;              // required in production (>= 32 chars); dev: process-stable random
  VELO_PUBLIC_ORIGIN: string;              // required in production: a bare https origin (http only on loopback), e.g. "https://velo.example"; dev: `http://localhost:${Number(VELO_DEV_PORT) || 8080}`
  GOOGLE_CLIENT_ID: string | undefined;    // required in production
  GOOGLE_CLIENT_SECRET: string | undefined;// required in production
  VELO_ADMIN_EMAILS: string[];             // parsed, lower-cased; may be empty
  VELO_EGRESS_PROXY: string | undefined;   // optional single operator proxy (socks5h:// or http://)
  VELO_PROXY_SECRET_KEY: string | undefined; // required in production when user proxies are enabled (32-byte key)
  VELO_PROXY_SECRET_KEY_PREVIOUS: string | undefined;
  VELO_EXTENSION_IDS: string[];            // Chrome extension ids allowed to handshake (W6)
  SENTRY_DSN: string | undefined;
  LOG_LEVEL: "debug" | "info" | "warn" | "error";
  YTDLP_PYTHON: string;                    // default "python3" on Linux, "python" on Windows
};
export class EnvError extends Error { readonly missing: string[]; } // every missing OR invalid name, never a value; message "Missing or invalid required environment variables: A, B"
export function loadServerEnv(source?: NodeJS.ProcessEnv): ServerEnv; // throws EnvError in production when a required var is missing or invalid, or BETTER_AUTH_TRUSTED_ORIGINS / BETTER_AUTH_SECRETS is set (Better Auth reads both directly, past C1/C9)
export function devOrigin(source?: NodeJS.ProcessEnv): string; // `http://localhost:${Number(VELO_DEV_PORT) || 8080}`: the dev default above, same expression as vite.config.ts
export function serverEnv(): ServerEnv; // memoized loadServerEnv(process.env)
```

Production boot runs `loadServerEnv()` in `server/plugins/env.ts`, a Nitro plugin that the node-server entry evaluates before it listens, so an `EnvError` exits the process non-zero. The plugin sets `NODE_ENV=production` first: the built server is production even when the shell leaves `NODE_ENV` unset. No C1 field is tied only to a feature W2 removes, so none is dropped.

### C3 — `src/lib/http/same-origin.server.ts` (created in W4a-T3)
```ts
export function requireSameOrigin(request: Request): Response | null; // null = allowed; otherwise apiError("cross_site", 403)
```
Rules: allow `Sec-Fetch-Site: same-origin`; allow a missing `Sec-Fetch-Site` only when `Origin` is absent or equals `VELO_PUBLIC_ORIGIN`; reject everything else. `POST` additionally requires `Content-Type: application/json`.

### C5 — No server-side execution of remote code (W4b)
**The one exception (controller ruling, 2026-09-24; pending counsel in W9):** yt-dlp may keep using its *own* bundled JavaScript solver. yt-dlp's cookie-capable YouTube clients need it, and D7 explicitly keeps "pinned yt-dlp with the user's own cookies". Conditions, all enforced in W4b-T8:
- the solver comes from the pinned, hash-locked install, never `--remote-components` or a download at run time;
- yt-dlp runs as a separate child process with an allowlisted environment, so it holds no server secrets;
- Velo's own code executes no player or BotGuard JavaScript, and adds no circumvention of its own.

If counsel rules otherwise, remove the JS runtime from the container (W5) and accept that signed-in yt-dlp downloads are lost.

There is no sandbox module. W4b deletes the code paths that execute remote JavaScript:
- PO-token/BotGuard minting (`src/lib/po-token.server.ts`);
- server-side signature/nsig deciphering (`/api/unlock` and its helpers);
- the `globalThis.window`/`document` swapping.

Every caller must degrade cleanly: no token → take the next normal extraction path, or return `apiError("upstream_failed", 502)`. `bgutils-js` and `jsdom` leave the dependencies if nothing else uses them.
